# Feature Specification: 参照ダッシュボード統合

**Feature Branch**: `[008-reference-dashboard]`

**Created**: 2026-08-09

**Status**: Draft — cross-modal linking policy pending

**Input**: User description: "参照HTMLとの差分を整理し、識別ごとの合計処理時間だけを表示し、話者識別結果がある場合は顔識別結果と顔ID・話者IDの区間重複率を表示する要件定義をまとめる"

## User Scenarios & Testing

### User Story 1 - 現行実装と参照画面の差分を確認する (Priority: P1)

レビュー担当者は、参照HTMLを採用した場合に、現行アプリから取得できる情報、取得できない情報、表示だけを追加できる情報を区別して確認できる。

**Why this priority**: 参照HTMLには現行アプリに存在しない集計値や端末情報が含まれており、実装前に「実測値」と「表示例」を混同しないことが必要だから。

**Independent Test**: 差分表を読み、各表示項目について「現行コードから取得可能」「追加計測が必要」「現行方針上表示不可」のいずれかを判定できる。

**Acceptance Scenarios**:

1. **Given** 現行アプリのメイン画面と参照HTMLを確認している, **When** 画面項目を比較する, **Then** レイアウト差分、指標差分、モデル・パラメータ差分、取得可否が一覧化されている。
2. **Given** 参照HTMLに表示例の値がある, **When** その値の採用可否を確認する, **Then** 実装で測定できない値は実測値として扱わず、表示例または取得不可として区別されている。

---

### User Story 2 - 参照HTMLに近いライブ画面を確認する (Priority: P2)

利用者は、白いヘッダー、左側の識別・計測領域、右側のカメラ・音声・端末状態領域を持つ画面で、顔識別と話者識別の現在状態を一度に確認できる。

**Why this priority**: 参照HTMLの価値は、識別状態と性能を同じ画面で把握できることにあるため。

**Independent Test**: カメラ権限なし、顔のみ、話者のみ、両方ON、両方OFF、無音、複数話者の各状態を表示し、状態の重複や欠落がないことを確認する。

**Acceptance Scenarios**:

1. **Given** カメラ権限がない, **When** ライブ画面を開く, **Then** カメラ領域、識別枠、顔ラベル・顔ID・類似度欄はレイアウト上に残り、未測定・未検出は明示される。
2. **Given** 話者識別がONで発話中, **When** 音声状態を表示する, **Then** 発話状態、現在の話者、話者ID、発話タイムラインが同じ音声カード内に表示される。
3. **Given** 無音または話者未検出, **When** 音声カードを表示する, **Then** 波形は灰色の無音表示となり、話者IDや区間重複率は `—` と表示される。
4. **Given** 画面幅が狭い端末を横向きで利用している, **When** 画面を閲覧する, **Then** 参照HTMLと同じ情報の優先順位を保ちつつ、横方向のレイアウトとスクロールで確認できる。

---

### User Story 3 - 識別ごとの合計処理時間を比較する (Priority: P1)

利用者は、処理過程の内訳ではなく、顔識別と話者識別それぞれの合計処理時間の平均を比較できる。

**Why this priority**: 指標の過程を増やすと参照画面との比較が難しくなり、プレビュー画面の情報密度も過剰になるため。

**Independent Test**: 顔識別または話者識別を実行し、表に合計処理時間が反映されること、内訳の行が表示されないこと、未実行時は `未測定` と表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 顔識別の測定値がある, **When** 計測表を表示する, **Then** 「顔識別 合計処理時間（ms）」の平均だけが表示される。
2. **Given** 話者識別の測定値がある, **When** 計測表を表示する, **Then** 「話者識別 合計処理時間（ms）」の平均だけが表示される。
3. **Given** いずれかの識別が未実行, **When** 計測表を表示する, **Then** 対応する値は `未測定` と表示され、参照HTMLの固定サンプル値を実測値として表示しない。

---

### User Story 4 - 顔識別・話者識別の結果履歴を確認する (Priority: P1)

利用者は、顔識別と話者識別の結果を別々の表で確認し、類似度・しきい値・1回の識別にかかった合計処理時間を比較できる。

**Why this priority**: 参照HTMLの結果表は、現在値だけでなく識別イベント単位の根拠を確認するために必要だから。

**Independent Test**: 顔識別と話者識別を実行し、それぞれの表に時刻、ID、類似度、合計処理時間が表示されることを確認する。話者表には発話時間も表示する。

**Acceptance Scenarios**:

1. **Given** 顔識別結果がある, **When** 顔識別表を表示する, **Then** 平均類似度、合計処理時間、しきい値、時刻、顔ID、類似度、処理時間（ms）が表示される。
2. **Given** 話者識別結果がある, **When** 話者識別表を表示する, **Then** 平均類似度、合計処理時間、しきい値、時刻、話者ID、類似度、処理時間（ms）、発話時間（s）が表示される。
3. **Given** 識別結果がない, **When** 結果表を表示する, **Then** 各値は `—` または `未測定` と表示され、固定サンプル値は表示されない。

---

### User Story 5 - 顔・話者の対応候補を確認する (Priority: P2)

利用者は、単独話者の発話が確定し、同じ時間窓に顔識別結果がある場合に限り、対応候補となる顔ID・話者IDと区間重複率を確認できる。

**Why this priority**: 顔と話者を同じ画面で扱う場合、対応関係の根拠と不確実なケースを明確にする必要があるため。

**Independent Test**: 単独話者、複数話者、無音、顔未検出、同率候補の各入力で、対応候補の表示条件と未確定表示を確認する。

**Acceptance Scenarios**:

1. **Given** 同じ発話窓に単独の話者IDと複数の顔トラックがある, **When** 対応候補を決定する, **Then** 発話窓との重複時間が最も長い顔トラックを第一候補とする。
2. **Given** 複数の顔トラックの重複時間が同じ, **When** 対応候補を決定する, **Then** 顔識別の類似度が最も高いトラックを選ぶ。
3. **Given** 複数話者、無音、顔未検出、または話者ID未確定, **When** 区間重複率を表示する, **Then** 顔ID・話者IDの対応と区間重複率は `—` または「複数話者／未確定」とし、推測で結び付けない。
4. **Given** 対応候補を表示する, **When** 利用者が画面を閉じるまたは初期化する, **Then** 対応関係はセッション外に残らない。

## 情報源の優先順位

1. **画面構成・表示項目・表の列**: 指定された参照HTML `Pepper検証アプリ メイン画面 (standalone) (2).html` を正とする。
2. **実測値・実際のモデル名・端末状態・権限状態**: 現行アプリの実装と実行時測定値を正とする。
3. **以前の `docs/current-screen.html`**: 画面仕様の情報源として採用しない。現行アプリとの接続に必要な識別IDや計測値だけ、実装上の互換情報として扱う。
4. **参照HTMLにない現行独自項目**: 利用価値と取得根拠が明確な場合を除き、追加しない。

## 現行アプリと参照HTMLの差分・取得可否

| 領域 | 参照HTMLの表示 | 現行アプリの状態 | 判定 |
|---|---|---|---|
| ヘッダー | 識別画面、経過、設定 | 識別画面、顔/話者ON-OFF、初期化、パラメータ、モデル。経過を表示し、設定画面へ切替可能 | 一部追加計測・表示が必要 |
| 顔識別 | カメラ、顔枠、ID、類似度、FPS | カメラ権限なしでも枠・顔ラベル・顔ID・類似度を表示。FPSは内部の計測値を持つ | 取得可能。見せ方の差分のみ |
| 話者識別 | VAD状態、波形、サンプリング情報、ノイズ除去・分離・特徴量の内訳 | 発話状態、dBFS、現在話者、話者ID、ラベル色付きタイムライン、ステージ計測値を保持 | 取得可能。ただし内訳は新画面では非表示 |
| 端末状態 | CPU、メモリ、温度、バッテリー | CPU、アプリPSSメモリを取得。温度・バッテリーはメイン画面の計測モデルにない | プレビューではCPU・メモリのみ表示し、温度・バッテリーは表示しない |
| 識別履歴テーブル | 顔/声ごとの時刻、ID、類似度、個別処理時間、発話秒数 | 識別結果と状態は保持するが、参照HTMLと同形式の履歴テーブルはない | 追加表示が必要 |
| イベントログ | 顔/声の時刻、類似度、新規ID、対応結果 | 識別結果と状態は保持するが、参照HTMLと同形式の画面イベントログはない | プレビュー画面に表示する |
| 類似度集計 | 顔平均、声平均、閾値色分け、新規ID件数 | 個別候補の類似度は取得。平均・新規件数の専用UIはない | 追加集計・表示が必要 |
| 顔・話者対応 | 顔IDと話者IDの対応、区間重複率 | 顔匿名IDと話者匿名IDは別状態 | 単独話者かつ区間重複率60%以上の場合のみセッション中に表示 |
| モデル | BlazeFace、MobileFaceNet、RNNoise、Silero VAD、pyannote-lite、ECAPA-TDNN | YuNet、SFace、Silero VAD、pyannote Segmentation 3.0、CAM++ Chinese-English等を選択 | 参照HTMLのモデル表示を基本採用。ただし実際にロードできないモデル名を実装済みとして表示しない |
| パラメータ | 参照HTMLの3列設定画面 | 現行アプリには顔、VAD、発話、音声品質、話者追跡等の実設定がある | 参照HTMLの項目・配置を基本採用し、値は実装値または取得不可で表示 |

## Requirements

### Functional Requirements

- **FR-001**: 画面は、参照HTMLの視覚的な情報階層（ヘッダー、メイン計測領域、右側のカメラ・音声・端末状態領域）を採用し、現行の顔/話者識別操作を維持しなければならない。
- **FR-002**: 顔識別と話者識別のON/OFFは、画面上の2つのトグル「顔識別」「話者識別」だけで独立操作でき、両方ON、両方OFF、片方のみONを許可しなければならない。「顔のみ」「話者のみ」「両方」の重複モードボタンは表示してはならない。
- **FR-003**: カメラ権限がない場合も、顔識別領域のレイアウトは保持するが、識別結果の値は表示せず、顔ラベル、顔ID、類似度など値がない項目は `—` と表示しなければならない。
- **FR-004**: 話者識別領域は、識別状態、発話状態、現在の話者、話者ID、発話タイムラインを一つのカードにまとめなければならない。無音は灰色、複数話者は黒、単独話者は話者ラベルごとの色で表示する。
- **FR-005**: カメラプレビューはPepperの横画面で640×480（4:3）を標準とし、映像を引き伸ばしたり切り抜いたりせず表示しなければならない。
- **FR-006**: 端末負荷はCPU（%）とメモリ（MB）の平均を右寄せで表示しなければならない。取得できない端末項目を固定サンプル値で補ってはならない。
- **FR-007**: 顔識別の性能指標は「顔識別 合計処理時間（ms）」1行、話者識別の性能指標は「話者識別 合計処理時間（ms）」1行を基本とし、顔検出、音声判定、話者検出、話者照合などの過程時間はメイン表に表示してはならない。
- **FR-008**: 性能表は平均の列だけを持ち、アプリ起動後に得られた全有効測定値を平均対象としなければならない。測定値がない場合は `未測定` を表示し、参照HTMLに埋め込まれた例示値を実測値として扱ってはならない。平均値はアプリ終了またはリセットで初期化し、永続保存してはならない。
- **FR-009**: 性能表にはRTFを表示せず、顔識別・話者識別それぞれの合計処理時間に絞らなければならない。
- **FR-010**: 顔識別結果表は、平均類似度、合計処理時間（ms）、閾値、時刻、顔ID、類似度、1回の識別処理時間（ms）を表示しなければならない。
- **FR-011**: 話者識別結果表は、平均類似度、合計処理時間（ms）、閾値、時刻、話者ID、類似度、1回の識別処理時間（ms）、発話時間（s）を表示しなければならない。
- **FR-012**: 結果表の「処理時間（ms）」は1回の顔識別または話者識別イベント全体の処理時間とし、VAD、話者検出、特徴量抽出などの過程内訳を結果表に追加してはならない。
- **FR-013**: モデルとパラメータは、参照HTMLの名称・値を無条件に採用せず、現行アプリで実際に選択・使用されるモデル名、ランタイム、設定値を表示しなければならない。
- **FR-014**: 顔と話者の対応は、同じ時間窓に単独話者の識別結果があり、顔識別結果が有効な場合に限り、重複時間が最長の顔トラックを候補とし、同率なら顔類似度が高い候補を選ばなければならない。区間重複率が設定値（初期値60%以上）の場合に限り、顔ID・話者ID・区間重複率を表示する。
- **FR-015**: 顔ID・話者IDの対応表示はセッション中の画面表示に限定し、顔画像、映像、音声、埋め込み、対応候補を永続保存してはならない。
- **FR-016**: 区間重複率が閾値未満、無音、顔未検出、または話者未確定の場合は、顔ID・話者ID・区間重複率を推測で補完せず `—` または `対応なし` と表示しなければならない。複数話者の場合は `複数話者` と表示し、顔ID・話者IDの対応を行ってはならない。
- **FR-017**: 参照HTMLにあるイベントログ、平均類似度、新規ID件数を表示する場合は、各項目の測定元と更新条件を定義し、取得できない環境では `取得不可` または `未測定` と表示しなければならない。新規ID件数はセッション中に初めて出現した匿名IDのユニーク件数を顔・話者別に集計し、実際の登録操作は提供しない。温度・バッテリーはプレビュー画面に表示してはならない。
- **FR-018**: 顔画像、映像、音声、埋め込み、顔・話者対応候補をアプリセッション終了後に保持してはならない。
- **FR-019**: イベントログは顔・話者識別イベントを `[{mm:ss.d}] FACE sim=0.000 → 顔ID FPnnn` または `[{mm:ss.d}] VOICE sim=0.000 → 話者ID SPnnn` の形式で出力し、顔ID・話者IDの種別を明示する。単独話者かつ区間重複率が閾値以上の場合は、VOICEログに `（顔ID FPnnn ／ 区間重複率 00%）` を追記し、対応できない場合も `（顔ID — ／ 対応失敗（理由））` または `（顔ID FPnnn ／ 区間重複率 00% → 対応失敗）` を追記する。操作メッセージを識別ログへ混在させてはならない。
- **FR-020**: 顔識別結果表、話者識別結果表、イベントログの時刻は、アプリ起動を基準とした同一の経過時間（`mm:ss.d`）で表示しなければならない。
- **FR-021**: 結果表とイベントログは画面上で表示可能な範囲だけを表示し、表示履歴を永続保存してはならない。画面表示のための一時的なメモリ保持は許可するが、アプリ終了またはリセットで破棄する。
- **FR-022**: 設定画面のモデルとパラメータは、既存Androidアプリの設定画面と同じ操作パターンで変更可能にする。変更対象は実際に端末へ搭載・ロードできるモデルとパラメータに限定し、変更値は現在の実装へ反映する。必要な実装パラメータは設定画面へ追加できる。
- **FR-023**: 顔識別の合計処理時間は顔検出処理の開始から顔ID決定まで、話者識別の合計処理時間はVAD処理の開始から話者ID決定までを測定範囲とし、カメラ・マイク取得時間とUI描画時間を含めてはならない。
- **FR-024**: 発話タイムラインは実マイク入力の短時間振幅（RMSまたはピーク）から、画面幅に収まる表示可能本数のバーを更新し、無音は灰色、単独話者は話者ラベルごとの色、複数話者は黒で表示する。無音でもタイムライン領域は残し、灰色の低いバーと `無音` を表示する。履歴は画面幅に収まるロール表示分だけを一時保持し、無限に伸ばしてはならない。入力解析は20〜50ms窓、UI描画は約100ms周期を推奨する。
- **FR-025**: Pepperは横画面、カメラ入力640×480（4:3）を標準とする。スマートフォンとタブレットも横画面で同じ3パネル構成を基本とし、画面高が不足する場合は縦スクロールを許可する。
- **FR-026**: 類似度の色分けは顔・話者の結果表の類似度セルに反映し、各表の上部に個別の凡例を表示する。区分名は `未達`、`判定可能`、`高信頼` とし、閾値未満、閾値以上かつ閾値+0.10未満、閾値+0.10以上に対応させる。顔は `<0.60`／`0.60〜0.69`／`≥0.70`、話者は `<0.75`／`0.75〜0.84`／`≥0.85` とする。全体の共通凡例バーは表示しない。新規ID件数は警告色ではなく通常色で表示する。

### Key Entities

- **識別測定値**: 顔識別または話者識別の1回分の合計処理時間、測定時刻、入力区間、測定状態。
- **顔識別結果**: 顔ラベル、顔ID、類似度、顔トラック、発生時間範囲。
- **話者識別結果**: 話者ラベル、話者ID、類似度、話者区間、発話状態。
- **対応候補**: 同じ時間窓における顔IDと話者IDの一時的な対応、重複時間、区間重複率、選択理由。設定された区間重複率閾値を満たす場合だけ有効化する。

## Success Criteria

### Measurable Outcomes

- **SC-001**: レビュー担当者が、参照HTMLの全表示項目について、現行アプリで取得可能か、追加計測が必要か、表示不可かを1つの差分表で確認できる。
- **SC-002**: 1280×800相当の横画面で、ヘッダー、カメラ、話者カード、端末負荷、合計処理時間表がスクロールなしで確認できる。
- **SC-003**: 性能表の識別処理行が、顔1行・話者1行の合計処理時間に整理され、過程時間とRTFの行が表示されない。
- **SC-004**: 未実行・無音・複数話者・カメラ権限なしの各状態で、未測定値と未確定値が固定サンプル値に置き換わらず明示される。
- **SC-005**: FR-011の方針決定後、単独話者かつ同一時間窓に顔結果があるケースだけで、選択理由（最長重複時間、同率時は顔類似度）を再現できる。
- **SC-006**: 顔識別表と話者識別表に、識別イベント単位の処理時間と結果根拠が表示され、過程時間の列が追加されない。
- **SC-007**: イベントログにFACE/VOICEの識別結果が指定形式で出力され、顔ID・話者IDの種別が明示される。

## Assumptions

- 指定された参照HTMLは、画面構成、情報階層、表示項目、モデル・パラメータ画面の基本仕様である。
- 参照HTMLのプレースホルダー値・サンプルログは実測値ではないため、実行時に取得できる値へ置き換える。取得できない場合は `未測定` または `取得不可` と表示する。
- 合計処理時間は、現行アプリが持つ顔識別・話者識別のパイプライン完了時間を正とし、表示する過程時間の合計を新たに推定して置き換えない。
- RTFは今回のプレビュー画面では表示しない。必要になった場合は別の詳細計測画面で再検討する。
- 温度・バッテリー・イベントログ・平均類似度・新規ID件数は、計測元が実装されるまで `取得不可` または `未測定` とする。
- 以前の `docs/current-screen.html` に固有の画面構成・履歴・説明は採用しない。現行アプリの実行に不可欠な権限、匿名ID、セッション限定保持、実測値だけを補助情報として残す。

## 確定した補足要件

- 顔識別の合計処理時間は、顔検出処理の開始から顔ID決定までを対象とする。
- 話者識別の合計処理時間は、VAD処理の開始から話者ID決定までを対象とする。
- カメラ・マイクの入力取得時間と、画面描画時間は識別処理時間に含めない。
- イベントログは画面に表示できる範囲だけを保持し、アプリ内ストレージや履歴DBには保存しない。
- Pepperのカメラプレビューは640×480（4:3）を標準とする。
- モデル名は画面に表示してよい。表示値は実際にAndroidで選択・ロードしているモデル名を優先する。
- カメラ権限がない場合は、識別結果を生成しない。顔ID・類似度・処理時間は `—`、状態は `未検出` と表示する。

## 顔・声の対応表示方針

- 同一発話区間に単独話者がある場合だけ、顔との重複時間が最長の顔を対応候補にする。
- 重複時間が同じ場合は顔類似度が高い候補を選ぶ。
- 区間重複率が設定値（初期値60%）以上の場合に、顔ID・話者IDと区間重複率を画面表示する。
- 複数話者時は話者ラベルのみ表示し、話者照合および顔IDとの対応付けは実施しない。
- 区間重複率が閾値未満、複数話者、無音、または未確定の場合は `—` と表示する。
- 対応表示はセッション中の画面表示に限定し、永続保存しない。
