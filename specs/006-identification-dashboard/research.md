# Research: 識別ダッシュボード

## 横画面共通レイアウト

- **Decision**: スマホとPepperで同じ横画面比率と領域順を使う。
- **Rationale**: スマホ検証をPepperレイアウトの先行検証として成立させるため。
- **Alternatives considered**: 端末別画面、縦横自動切替。差分が増え、Pepper受入前検証にならないため不採用。

## サンプル動画

- **Decision**: MP4をAPK資産へ同梱し、負荷検証設定で選んだ1本だけをAndroid標準VideoView/MediaPlayerでミュート再生する。初期値は非表示とする。
- **Rationale**: API 23互換を保ち、新規動画ライブラリを追加しないため。
- **Alternatives considered**: 外部ストレージ、ネットワーク配信、追加プレイヤーライブラリ。オフライン性またはAPK互換性の負担から不採用。

## 音量グラフ表示

- **Decision**: 計測値はdBFSのまま保持し、利用者向けグラフは-90～0 dBFSを0～100%へ変換して正数表示する。
- **Rationale**: dBFSの負数目盛りによる誤解を避けつつ、録音・VAD処理の既存契約を変更しないため。
- **Alternatives considered**: dBFS負数のまま説明を追加する方式。画面の直感性が下がるため不採用。

## モデル選択

- **Decision**: モデルと推論基盤を1つのセットとしてプルダウン表示する。
- **Rationale**: 非対応組合せを作れず、実行した資産と基盤を明示できるため。
- **Alternatives considered**: 2つの独立プルダウン、無効候補の常時表示。誤構成または画面占有が増えるため不採用。

## 端末受入順

- **Decision**: ARM64スマホの横画面・操作・動画・クラッシュ確認後にARMv7 Pepperへ進む。
- **Rationale**: Pepperインストール時間を節約し、レイアウト不具合を早期に除去するため。
- **Alternatives considered**: 並行導入、Pepper先行。ユーザー指定の受入順に反するため不採用。

## 詳細パラメータの適用

- **Decision**: 全調整値を設定モデルへ集約し、顔検出・追跡、VAD・発話区切り、音声品質、話者追跡の生成時に注入する。
- **Rationale**: 画面だけ変更されて実処理が固定値のままになる不一致を防ぎ、保存した試験条件を再現できるため。
- **Alternatives considered**: UI表示のみ、グローバル可変値、モデル契約値まで設定可能にする方式。再現性、境界検証、モデル互換性を損なうため不採用。
